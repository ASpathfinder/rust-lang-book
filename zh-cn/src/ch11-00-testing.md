# 编写自动化测试

Edsger W. Dijkstra 在 1972 年的文章《谦逊的程序员》中说：“程序测试可以非常有效地证明 bug 的存在，却完全无法充分证明它们不存在。”但这并不意味着我们不应该尽可能多地测试！

程序的<em>正确性(correctness)</em>是指代码在多大程度上完成了我们想让它做的事情。Rust 的设计高度重视程序正确性，但正确性很复杂，也不容易证明。Rust 的类型系统承担了这项重任的很大一部分，但类型系统无法捕获所有问题。因此，Rust 提供了编写自动化软件测试的支持。

假设我们编写一个 `add_two` 函数，把传给它的任意数字加 2。该函数的签名接收整数形参，并返回一个整数结果。实现并编译该函数时，Rust 会执行你目前学过的所有类型检查和借用检查，例如确保我们没有向函数传入 `String` 值或无效引用。但是，Rust<em>无法</em>检查这个函数是否会准确完成我们的意图，也就是返回形参加 2，而不是形参加 10 或形参减 50！这正是测试发挥作用的地方。

例如，我们可以编写测试来断言：向 `add_two` 函数传入 `3` 时，返回值为 `5`。每次修改代码后都可以运行这些测试，确保现有的正确行为没有发生变化。

测试是一项复杂的技能：一章无法涵盖如何编写良好测试的每个细节，但本章会讨论 Rust 测试工具的运作机制。我们会介绍编写测试时可用的标注和宏、运行测试时提供的默认行为和选项，以及如何把测试组织为单元测试和集成测试。

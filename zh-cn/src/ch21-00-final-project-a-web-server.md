# 最终项目：构建多线程 Web 服务器

这是一段漫长的旅程，但我们已经来到本书末尾。本章会一起再构建一个项目，展示最后几章介绍的一些概念，同时复习之前的课程。

在最终项目中，我们会制作一个显示“Hello!”的 <em>Web 服务器(Web server)</em>，它在浏览器中看起来如图 21-1 所示。

构建 Web 服务器的计划如下：

1. 简单了解 TCP 和 HTTP。
2. 在<em>套接字(socket)</em>上监听 TCP 连接。
3. 解析少量 HTTP 请求。
4. 创建正确的 HTTP 响应。
5. 使用<em>线程池(thread pool)</em>提升服务器的<em>吞吐量(throughput)</em>。

开始之前，需要说明两个细节。第一，我们采用的方法并不是使用 Rust 构建 Web 服务器的最佳方式。社区成员已经在 [crates.io](https://crates.io/) 发布了许多可用于生产的 crate，它们提供的 Web 服务器和线程池实现比我们将要构建的更加完整。不过，本章的目的在于帮助你学习，而不是走捷径。Rust 是系统编程语言，因此可以选择想要使用的抽象层级，也可以深入到其他语言无法或不宜触及的更低层级。

第二，我们在这里不会使用 async 和 await。构建线程池本身就已是足够大的挑战，无需再加上构建异步运行时！不过，我们会指出 async 和 await 可以如何应用于本章将看到的一些相同问题。归根结底，正如第 17 章所说，许多异步运行时也使用线程池管理工作。

因此，我们会手动编写基本 HTTP 服务器和线程池，让你理解未来可能使用的 crate 背后的一般思想与技术。

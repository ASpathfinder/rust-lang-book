## 循环与迭代器的性能

要决定使用循环还是迭代器，需要知道哪种实现更快：使用显式 `for` 循环的 `search` 函数版本，还是使用迭代器的版本。

我们运行了一项基准测试，把 Sir Arthur Conan Doyle 的《福尔摩斯探案集》全文加载到 `String` 中，并在内容中搜索单词 <em>the</em>。以下是使用 `for` 循环的 `search` 版本和使用迭代器版本的基准测试结果：

```text
test bench_search_for  ... bench:  19,620,300 ns/iter (+/- 915,700)
test bench_search_iter ... bench:  19,234,900 ns/iter (+/- 657,200)
```

两种实现的性能相近！这里不会解释基准测试代码，因为目的并不是证明两个版本完全等价，而是对这两种实现在性能上的比较有一个总体认识。

要进行更全面的基准测试，应该使用各种不同大小的文本作为 `contents`，使用不同单词和不同长度的单词作为 `query`，并检验其他各种变化。关键在于：迭代器虽然是高层抽象，但会编译成与自己编写底层代码大致相同的代码。迭代器是 Rust 的<em>零成本抽象(zero-cost abstraction)</em>之一，也就是说，使用抽象不会产生额外运行时开销。这类似于 C++ 的最初设计者和实现者 Bjarne Stroustrup 在 2012 年 ETAPS 主题演讲《Foundations of C++》中对零开销的定义：

> 一般而言，C++ 实现遵循零开销原则：不使用的功能，不必为其付出代价。此外，使用的功能，也无法通过手写代码做得更好。

在许多情况下，使用迭代器的 Rust 代码会编译成与手写代码相同的汇编。循环展开、消除数组访问边界检查等优化会应用于代码，使最终代码极为高效。知道这一点后，就可以放心使用迭代器和闭包！它们让代码看起来处于更高层次，却不会造成运行时性能损失。

## 总结

闭包和迭代器是 Rust 中受函数式编程语言思想启发的功能。它们有助于 Rust 以底层性能清晰表达高层概念。闭包和迭代器的实现方式不会影响运行时性能。这是 Rust 努力提供零成本抽象这一目标的一部分。

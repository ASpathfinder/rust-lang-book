## 附录 E：版本

第 1 章中你看到，`cargo new` 会在 <em>Cargo.toml</em> 文件中添加一点有关版本的元数据。本附录将解释它的含义！

Rust 语言和编译器采用六周发布周期，意味着用户会持续获得新功能。其他编程语言不那么频繁地发布较大更改；Rust 则更频繁地发布较小更新。经过一段时间后，所有这些细小变化会积少成多。但是，从一次发布到下一次发布，很难回头感叹：“哇，在 Rust 1.10 与 Rust 1.31 之间，Rust 发生了很大变化！”

大约每三年，Rust 团队会推出一个新的 Rust <em>版本(edition)</em>。每个版本都会把已经落地的功能汇集成一套清晰的软件包，并提供全面更新的文档和工具。新版本作为通常的六周发布流程的一部分发布。

版本对不同人群有不同用途：

- 对活跃的 Rust 用户来说，新版本把渐进式更改汇集成一套容易理解的软件包。
- 对尚未使用 Rust 的人来说，新版本表明已经落地了一些重大进展，可能值得重新关注 Rust。
- 对 Rust 开发者来说，新版本为整个项目提供了一个共同努力的节点。

撰写本书时，有四个 Rust 版本可用：Rust 2015、Rust 2018、Rust 2021 和 Rust 2024。本书使用 Rust 2024 版的惯用写法编写。

<em>Cargo.toml</em> 中的 `edition` 键指出编译器应为代码使用哪个版本。如果该键不存在，出于向后兼容的原因，Rust 会使用 `2015` 作为版本值。

每个项目都可以选择采用默认 2015 版之外的版本。版本可以包含不兼容更改，例如加入会与代码中标识符冲突的新关键字。不过，只要没有选择采用这些更改，即使升级所用的 Rust 编译器版本，代码仍会继续编译。

每个 Rust 编译器版本都支持在该编译器发布之前已经存在的所有版本，并且可以把任何受支持版本的 crate 链接在一起。版本更改只影响编译器最初解析代码的方式。因此，如果你使用 Rust 2015，而某个依赖使用 Rust 2018，项目仍然可以编译并使用该依赖。反过来，项目使用 Rust 2018、依赖使用 Rust 2015 的情况也同样可行。

需要说明的是：大多数功能在所有版本中都可用。无论使用哪个 Rust 版本，开发者都会随着新的稳定版发布持续看到改进。然而，在某些情况下——主要是添加新关键字时——部分新功能可能只在较新的版本中可用。要利用这类功能，就需要切换版本。

有关更多详情，请参阅 <em>[Rust 版本指南(The Rust Edition Guide)][edition-guide]</em>。这本完整的书列出了各版本之间的差异，并解释如何通过 `cargo fix` 把代码自动升级到新版本。

[edition-guide]: https://doc.rust-lang.org/stable/edition-guide

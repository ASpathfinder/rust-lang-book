# 无畏并发

安全而高效地处理并发编程，是 Rust 的另一项主要目标。随着越来越多的计算机利用多个处理器，程序不同部分独立执行的<em>并发编程(concurrent programming)</em>，以及程序不同部分同时执行的<em>并行编程(parallel programming)</em>，正变得日益重要。过去，在这些环境中编程既困难又容易出错，Rust 希望改变这一点。

最初，Rust 团队认为确保内存安全和防止并发问题是两项独立的挑战，需要用不同方法解决。随着时间推移，团队发现所有权和类型系统是一套强大的工具，既能帮助管理内存安全，<em>也</em>能处理并发问题！通过利用所有权和类型检查，Rust 中的许多并发错误会成为编译期错误，而不是运行时错误。因此，错误代码会拒绝编译，并给出解释问题的错误消息，不必耗费大量时间去重现运行时并发 bug 发生的确切条件。这样，你可以在编写代码时就修复问题，而不必等到它可能已经发布到生产环境之后。我们把 Rust 的这一特性称为<em>无畏并发(fearless concurrency)</em>。无畏并发让你能够编写没有微妙 bug 的代码，并能轻松重构而不引入新的 bug。

> 注意：为简单起见，我们会把许多问题称为“并发”，而不使用更精确的“并发和/或并行”。在本章中，每当看到“并发”，请在心中将其替换为“并发和/或并行”。下一章中两者的区别更加重要，届时我们会更精确地表述。

许多语言对如何解决并发问题持有相当明确的立场。例如，Erlang 为消息传递并发提供了优雅的功能，却只有一些晦涩的方法在线程间共享状态。对高级语言而言，只支持可能方案的一个子集是一种合理策略，因为高级语言承诺通过放弃部分控制来获得抽象带来的好处。然而，人们期望低级语言能够针对任何给定场景提供性能最佳的方案，并且对硬件的抽象更少。因此，Rust 提供了多种工具，可以根据你的场景与需求，以任何合适的方式为问题建模。

本章将介绍以下主题：

- 如何创建线程，同时运行多段代码
- <em>消息传递(message-passing)</em>并发，其中通道在线程之间发送消息
- <em>共享状态(shared-state)</em>并发，其中多个线程可以访问某一份数据
- `Sync` 和 `Send` trait，它们把 Rust 的并发保证扩展到用户自定义类型以及标准库提供的类型
